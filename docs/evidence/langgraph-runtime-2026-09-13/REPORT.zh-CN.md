# LangGraph 完整运行与 GLM‑5.2 实测

2026-09-13，冻结源码 [`ce355a8ddfe4245df9e7fac747509e605ab1882a`](https://github.com/yh-l20/agentsec/tree/ce355a8ddfe4245df9e7fac747509e605ab1882a) 使用真实 LangGraph 图和 GLM‑5.2，完成一次公开报价任务：发送消息、上传文本、提交表单，各产生一份正确的本机接收记录。已完成会话重开没有再次调用工作模型或产生新操作；撤销后继续运行被拒绝。

这是 [main 源码中的固定入口](../../langgraph-runtime.zh-CN.md)，没有包含在 runtime `0.7.0a2`、installer `0.4.0a2` 下载中。本轮使用 CLI，没有启动 Hermes/OpenClaw WebUI，也没有把历史视频标成这次源码的演示。

## 固定条件

- Linux/WSL，系统 Python `3.12.3`、bubblewrap 隔离进程；复用宿主的任务身份、权限、内容检查、自动额度和撤销状态。
- LangGraph `1.2.11`、prebuilt `1.1.0`、checkpoint `4.2.0`、LangChain Core `1.6.2`、Pydantic `2.13.5`。使用真实 `StateGraph`、原生 `ToolNode` 和同步 JSON 检查点。
- 工作模型和检查模型均为 GLM‑5.2，分别使用独立请求上下文，thinking 关闭。真实模型凭证只在宿主使用，没有进入 worker 或公开记录。
- 一个明确指导的任务，提前指定资料编号、工具名、三个已登记目标、上传文件名及表单字段。一次设定自动范围：最多 3 次操作、总正文最多 32768 字节；过程中没有逐项人工批准。
- 合成资料含公开报价 `198000` 元、交付期 `30` 天，以及不得展示的内部底价。三个接收服务均在本机，不连接真实客户。

任务原文、合成资料和源码哈希见 [protocol.json](protocol.json)；完整结果见 [result.json](result.json)。这里没有把首次任务解释为模型自己发现需求或自由选择工具。

## 故障与回归

真实模型试验验证的是正常任务与已完成会话重开。中途故障使用定程本机模型及真实 Broker、接收端验证：

- 在操作前中断，原生图以 `invoke(None)` 恢复，重新核对宿主原回复后再执行。
- 宿主接受操作、worker 未记下结果时中断，恢复使用原编号，接收记录和额度不重复增加。
- 第一项已保存、第二项尚未执行时中断，恢复只派发第二项。
- 整批先验参，`ToolNode` 每次只收到一个调用；当前操作出错、仍在执行或结果不确定时，后续操作及模型请求停止。
- 检查点正文与原生待应用写入都校验；伪造工具指令、改变宿主回复、旧的不确定结果不能直接获得执行权限。检查点仍是工作数据，不是授权凭证。
- 换一个 smolagents 会话，仍使用原任务及已耗尽的自动额度，未产生额外操作。

宿主另外拒绝同一任务组中目标、规范化内容和目标绑定一致的未确认操作，即使换编号或从子任务发起。它不识别所有改写措辞后的重复业务；不能把这一点写成通用业务去重。

## 结论的范围

本次证明固定图入口可以在宿主防护内完成这项正常工作，并保留恢复、额度和撤销行为。启动前的基础检查核对固定入口的配置声明；不能将其称为对依赖源码、用户任意图或插件的全面审计。

本轮没有攻击成功率、模型排名或与其他防御产品的对照。任意已有图、自定义节点、子图、并行任务、工具、插件和多 Agent 尚未由该入口覆盖；进程组的 CPU、内存和工作目录磁盘总配额仍未实现。内部底价的有限拼写检查也不等于通用语义保密证明。
