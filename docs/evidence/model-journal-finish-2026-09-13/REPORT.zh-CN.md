# 模型回复发出前完成宿主记录

修复源码 `82c02f4fc69ea6d053b4a24f085d4738e3d99904`。客户端收到模型回复后立即恢复或核验会话时，旧实现可能尚未结束本次宿主记录操作，从而返回 409；模型请求失败时，还可能在错误回复发出后才保存“结果未确认”状态。

公开提交 `01a712500672e489779712189359914596fa0760` 的 [Checks](https://github.com/yh-l20/agentsec/actions/runs/34732548636) 和[执行边界检查](https://github.com/yh-l20/agentsec/actions/runs/34732548634)实际发现了这个时序问题。此前本地测试通过没有排除该竞争。

现在，新回复、已保存回复和错误回复都会先结束宿主记录操作，再发送 HTTP 回复。记录收尾失败返回 409；连接清理仍会执行。只查询已保存回复的入口不创建新记录，也不触发模型生成。

三项新增测试分别暂停成功请求、失败请求和缓存请求的记录收尾，检查客户端此时不能收到回复，再放行并立即查询。相同测试在旧源码 `6543f54` 上均准确失败，在修复版上通过。独立复审的完整模型通道测试 10/10 通过，包含缓存收尾仅失败一次时的错误状态与清理检查。

两个平台的 486 个功能文件在测试前后均与冻结 Git 内容一致；207 项记录一致性检查通过。环境沿用前次独立环境，重新核对五组依赖版本，没有重新安装或修改依赖。[机器可读记录](verification.json)包含逐模块数量、旧源码反证和原始本地记录的哈希。本页记录本地回归，公开 CI 结果以[对应提交的 Actions](https://github.com/yh-l20/agentsec/actions)为准。
