# 用元星木建立一份 AI 工作

元星木为每项工作单独保存资料和权限。在页面里选择 OpenClaw 或 Hermes、连接模型、导入短文本，就可以进入助手原来的聊天界面工作。

**你选择的模型会看到聊天和使用的资料。** 云端模型会接收这些内容；元星木限制的是额外的资料读取和发送。默认不向其他位置自动发送。创建时可授权固定的消息、上传和表单对象，检查通过后自动完成；邮件仍需逐封核对并确认。明确标记的敏感字段会先隐藏，具体范围见下文。

这是 Linux / WSL 预览版，首次安装仍需要终端。安装完成后，连接模型、导入资料、打开和关闭工作都可以在页面中完成。**`0.7.0a2` 运行包已发布，包含 Hermes、五层检查、授权内自动操作和敏感字段保护；[配套 `0.4.0a2` 安装器](https://github.com/yh-l20/agentsec/releases/tag/installer-0.4.0a2)也已发布。** 按[官网安装步骤](https://yh-l20.github.io/agentsec/start.html)装到独立的新目录。旧安装和旧工作不会自动升级。当前版本固定接入 OpenClaw 2026.9.4、Hermes v2026.9.11 / 0.21.2；真实运行结果及未通过项分别见 [OpenClaw](openclaw-layers-validation-2026-09-12.md) 和 [Hermes](../yuanxingmu/integrations/hermes/VALIDATION.zh-CN.md)。

## 第一次打开

先按[官网安装步骤](https://yh-l20.github.io/agentsec/start.html#install)使用 0.4.0a2 安装器，明确指定新的 `~/yuanxingmu-v07a2` 目录。装好后，在同一个 Ubuntu 终端运行：

```bash
"$HOME/yuanxingmu-v07a2/open-yuanxingmu"
```

如果安装时改过目录，请使用那个目录中的 `open-yuanxingmu`。安装器在不传 `--install-root` 时仍默认使用 `~/yuanxingmu`；本文步骤明确指定 `~/yuanxingmu-v07a2`，以便保留旧安装。

以前按[手工安装说明](openclaw-quickstart.zh-CN.md#1-安装到一个独立目录)安装的，继续使用原入口。原来装在 `~/yuanxingmu` 时，命令是：

```bash
"$HOME/yuanxingmu/.venv/bin/python" -I -m yuanxingmu desk
```

程序会打开本机工作台。如果浏览器没有自动打开，复制终端中完整的 `http://127.0.0.1:18910/#access=…` 链接到这台电脑的浏览器。

这个链接是你的管理入口，请只供自己使用。它与 OpenClaw / Hermes 的聊天入口不同。重新启动工作台会生成新的管理链接；工作和原有权限仍然保留。

旧安装继续使用原入口。试用新版本时使用独立的新目录；不要覆盖旧安装、修改已建工作的权限文件或运行版本来强行升级。更换程序也不会把旧工作自动变成启用新防护的工作。

## 在页面里建立第一项工作

1. **选择助手、起个名字。** 例如选择 Hermes，工作名称填写“整理活动预算”。页面只允许选择本机已经安装的助手。
2. **说明这份工作要完成什么。** 例如“读取活动报价，计算总预算，在聊天中回复；不要外发资料或删除文件”。这份要求创建后固定，文件里的指令不能替你改变它。
3. **填写模型连接。** 输入模型服务给你的接口地址、模型名称和 API 密钥。需要支持 Chat Completions 和工具调用的模型接口；网页聊天账号本身不是接口。云端地址用 HTTPS，本机服务可用 `http://127.0.0.1:1234/v1` 一类地址；本机无密钥服务可以留空。
4. **导入一份短文本。** 选择 UTF-8 的 `.txt` 或 `.md` 文件，给它一个聊天时能引用的名称，例如 `quote`。
5. **创建并打开工作。** 点击“创建独立工作”。创建成功后，在卡片中点击“启动工作”；启动会先检查设置和所选技能。完成后再点“进入 OpenClaw”或“进入 Hermes”，打开真正的聊天界面。

模型密钥会保存在这台电脑的工作目录中，供后续重新打开使用。页面不会把它放进浏览器存储或操作记录。

可以先把下面内容保存为 `quote.txt`，然后在页面选中这个文件：

```text
项目：春季客户活动（练习资料）
场地：6000 元
物料：2800 元
摄影：1200 元
备注：报价仅供内部讨论，尚未确认供应商。
```

当前最多 8 份文本，每份 256 KiB，合计 1 MiB。PDF、Word、Excel 和图片还不能直接导入。模型能否一次读完，另受它的上下文长度限制。

创建时会保存文件副本。后来修改原文件，不会改变这项工作的资料；本版要换资料时请建立新工作。

## 去助手原来的页面聊天

点击页面提供的聊天入口，输入：

> 请读取 quote，列出三个费用项目，算出总费用，并说明还有什么需要确认。直接在聊天里回复我。

这份练习资料合计 **10,000 元**，供应商尚待确认。你可以继续要求“改成三句话”或“整理成表格”。模型仍可能读错资料或算错；元星木控制操作权限，答案需要你核对。

聊天窗口是所选助手自带的界面。工作台负责管理这项工作，不另外模拟一套聊天或生成演示回答。当前新入口会等模型回答收齐并完成检查后再显示，因此不会逐字出现。

## 五层检查分别管什么

| 页面上的功能 | 它检查什么 |
| --- | --- |
| 安装与技能检查 | 启动前检查设置和你选中的技能副本，例如是否允许直接联网、技能里是否藏着越权指令。 |
| 外部内容检查 | 文件或工具结果里是否冒充用户、要求忽略原任务或索取凭证。 |
| 记忆防投毒 | AI 是否准备把绕过安全、偷偷发资料等要求写成以后一直遵守的记忆。 |
| 任务偏移检查 | AI 当前准备做的事、准备显示的回答，是否违背你创建工作时写下的要求。 |
| 危险命令检查 | 在命令执行前检查提权、破坏文件、窃取凭证、下载执行等行为。 |

默认开启五层，并实际拦截或等待本人核对。选择“只记录，不拦截”后，命中记录不能当成已阻止。可在“防护记录”中查看各层当前状态；新建工作支持运行中调整开关，旧工作须确认关闭后才能修改。改设置不会自动解除暂停，也不会扩大资料和发送权限。

默认由同一个模型做事和检查。需要时，在创建页展开“用另一个模型做防护检查”，填写另一套连接。检查模型也会接收任务要求、候选操作、技能内容及回答文字；不能把接入成功当成判断可靠。当前小模型实测存在正常写入误报，详见[检查模型说明](judge-configuration.zh-CN.md)。

检查需要你确认某一步代码时，工作台会显示完整候选和“只允许这一次”。批准不等于允许后续任意命令；参数改变或许可过期都需要重新核对。明确命中的危险硬规则不能靠这次批准跳过。

## 让 AI 起草邮件，由你确认发送

新建的工作卡片中有“查看邮件草稿”。先在“发件邮箱设置”中填写自己的邮箱连接，再让 AI 起草。打开草稿，核对收件人、主题和全文；需要改动时保存修改，再重新确认。只有点击“确认发送这封邮件”才提交邮件，AI 没有这个确认入口。

发送完成后保留实际结果。显示结果不明时，先到邮箱核对，不要重复发送。每封草稿只有一次提交机会；邮箱服务接收不等于对方收到或阅读。详见[邮件使用步骤](email.zh-CN.md)。旧工作不会自动启用邮件功能。

## 哪些操作可以自动完成

在工作台的“可确认的操作对象”中先登记目标，再让 AI 提交申请。例如登记团队消息接收地址，或选定允许覆盖的报告文件。AI 只能引用已经登记的对象，不能自己换成别的地址或文件。

创建新工作时，可在“自动执行范围”中勾选“让 AI 在选定范围内自动完成”，再选择已登记的消息、上传或表单对象。通过资料权限、额度和防护检查后，这些对象上的操作会自动执行，无需逐项批准；工作台保留真实结果。没有勾选的对象仍需核对，邮件、覆盖和删除文件也不在这项自动范围内。详见[一次设好范围，让 AI 自己完成](automatic-work.zh-CN.md)。

对于待确认的操作，打开记录，核对目标和全部内容，再决定是否执行。覆盖文件会展示原有全文和替换全文；删除只针对登记过的那份文件。目标或内容改变后要重新核对。传输结果不明时先检查接收端，不自动重复执行。

当前消息、上传、表单采用已实现的固定协议；本机接收端验证不等于任意第三方平台都能直接接入。文件操作限显式登记的小型既有 UTF-8 文件；不支持任意目录删除或通用文件管理。

## 敏感字段和可疑资料怎样处理

`0.7` 新建工作会先隐藏资料中明确标记的底价、密码和令牌，再交给模型。完整回答、工具参数、检查模型请求和实际提交也会检查已登记的值。这道保护不受五层语义检查开关控制；命中时会扣留内容并暂停后续操作。它只覆盖固定标签和有限格式，不能保证发现未标记、任意编码或推算出的秘密，详见[敏感字段保护](protected-fields.zh-CN.md)。

如果外部资料因夹带指令被整段扣留，且防护记录成功，其他已授权工作可以继续，无需反复点恢复。危险命令、记忆投毒或回答越界等情况仍可能暂停工作。更新程序不会给旧工作自动追加这些防护。

## 被暂停后怎么继续

工作台会显示暂停原因。打开“防护记录”，核对并处理全部未解决的问题，再勾选确认、点击“恢复这份工作”。继续发聊天、重开页面或等待，不会自行解除暂停。

恢复后回到助手页面重新提出需要完成的任务；旧操作和旧审批不会自动重试。遇到“已停止但结果不明”的操作，先查实际文件或收件记录。暂停不能撤回已经完成的发送。

需要离开网页时，可配置[后台提醒](background-notifications.zh-CN.md)。浏览器关闭后，运行中的工作台仍可把暂停、恢复、撤权和待审批状态发到固定接收地址；工作台进程退出后不会继续发送。

## 下次继续，还是彻底收回权限

| 你想做什么 | 页面操作 | 实际效果 |
| --- | --- | --- |
| 今天先不用了 | 暂时关闭 | 关闭这项工作及其运行中的命令。正常关闭后可继续原来的工作。 |
| 继续整理资料 | 启动工作 / 获取聊天入口 | 使用原来的资料、聊天和权限，再进入所选助手的页面。 |
| 查看是否还在运行 | 刷新状态 | 查看实际状态，不修改权限。 |
| 永久禁止继续读取、发送资料 | 永久收回权限 | 需要再次确认；此版本不能恢复。重新打开或换会话不会恢复权限。 |

收回权限不会删除 AI 已经读到的内容，不会撤回过去完成的发送，也不会停止本地计算。需要一起结束运行时，再点击“暂时关闭”。

**关闭浏览器标签页或退出工作台，不会关闭运行中的 AI。** 先在页面关闭需要结束的工作，再退出终端中的工作台。

页面显示异常或“尚未确认关闭”时，不代表服务已经安全退出。请保留目录和日志，确认进程情况；不要删除权限记录或修改状态绕过检查。

## 文件保存在哪里

按本文安装器步骤安装时，保存在 Linux 的 `~/yuanxingmu-v07a2/workbench` 下。旧版或手工安装在 `~/yuanxingmu` 时，仍使用 `~/yuanxingmu/workbench`。其他安装位置使用对应目录；以启动时的设置为准：

- `profiles/`：每项工作的资料副本、聊天、模型密钥和权限记录。
- `catalog.json`：工作名称和操作记录，不包含模型密钥和资料正文。

这些位置仅供当前系统用户访问。它不是多人共享的管理平台；不要把工作台端口代理到公网。程序只监听 `127.0.0.1`，不会提供绑定外网的选项。

页面提交失败时，再次确认实际状态。对同一次网络请求的重试会返回原操作，工作台重启后也不会自动重新执行未确认的操作。

如果电脑断电或程序异常退出，有些工作可能需要检查后才能继续。本版没有删除、重置权限或修复缺失记录的按钮。

## 安装在其他位置

终端可以指定安装位置，或显式指定已经安装的运行文件。浏览器页面不能提交这些路径或任意命令。

```bash
python -I -m yuanxingmu desk \
  --install-root /home/me/yuanxingmu \
  --data /home/me/yuanxingmu/workbench \
  --node /home/me/yuanxingmu/tools/node-v24.16.0-linux-x64/bin/node \
  --openclaw-package /home/me/yuanxingmu/openclaw/node_modules/openclaw \
  --bwrap /usr/bin/bwrap
```

工作台数据目录首次使用时应不存在；已有工作台使用原目录。不要预先创建一个空的 `workbench` 目录。运行时只能有一个工作台管理同一目录。

手工安装 Hermes 时，还可指定 `--hermes-python /home/me/hermes/env/bin/python` 与 `--hermes-source /home/me/hermes/source`；必须是支持版本、已经构建官方网页的环境。仅安装 Python 包不代表网页已可运行，具体要求见 [Hermes 接入说明](../yuanxingmu/integrations/hermes/README.md)。

更详细的[命令行使用和排错](openclaw-quickstart.zh-CN.md)、[运行机制与边界](openclaw-runtime.md)仍然保留。
